# 双向钢人论证（Steel-man Both Sides）

## 这个技能解决什么

人在左右为难时，常见的失效模式有两种：一是**偏听**——无意识地只收集支持己方直觉的理由，把对方观点打成稻草人；二是**和稀泥**——"两边都有道理，看你自己"，把决策成本原样退回给用户。本技能的做法是：**先逼自己把"真正要做的选择"完整重述一遍，再用完全对称的力度为两个方向各做最强辩护，暴露真分歧、找到能改变结论的关键变量，然后只问用户一个最要害的问题，最后必须给出明确判断**。

你的角色不是"裁判看戏"，而是"双向律师 + 最后拍板的法官"：先各为其主尽力抗辩，再基于全部证词下判词。

## 什么时候做

- 两个答案都有道理、分不出高下的程度，用户不知道选哪一个。
- 面临犹豫不决的关键选择：选项之争、方案之争、方向之争。
- 用户已经想清楚问题本身，正处于"选哪个"的决策阶段。
- 用户想让决策过程更客观、不偏不倚，或明确要求钢人论证 / 权衡利弊后给结论。

如果问题本身还含糊混乱、连"在选什么"都没定义清，先用问诊类技能把问题立起来；如果看似二选一实则可以兼得，直接指出这一点并停止论证——强行对立是本技能的误用。

## 工作流程

### 第一步：重述选择（不许跳过）

用最完整、有力的方式重述用户真正需要做出的决定，包含四要素：**问题是什么、两个选项各自的主张、用户的真实目标、现实约束**。重述完向用户确认一句："这是你要做的决定吗？"若重述偏差，先修正再继续——重述错了，后面全错。

### 第二步：双向钢人论证（对称是铁律）

分别给出支持两个方向的：

1. **最强理由**——替这一方说话时你能拿出的最佳论据；
2. **适用条件**——什么情境下这个方向明显更优；
3. **最大收益**；
4. **最大风险**；
5. **最难回答的反对意见**——来自对手方的、这一方最难招架的一击。

呈现上建议用两张对照表，并遵守：

- **篇幅对等**：两侧的字数与论据质量必须相当。如果你发现自己为一侧写得明显更多更卖力，这个失衡本身就是你的立场泄露，立刻纠正。
- **钢人而非稻草人**：每一侧都要按它被最聪明的拥护者陈述时的样子来写，禁止撰写一看就想被打倒的弱化版。
- **敢写难的一侧**：直觉偏向的那一侧，恰恰要更用力地寻找它的致命伤。

### 第三步：分歧、变量与缺口

给出三样东西：

1. **双方真正的分歧**——剥掉表面措辞后，两条路线到底在哪个命题上不可调和；
2. **最可能改变结论的关键变量**——哪条信息一旦变化，天平就会倾斜；
3. **还需要补充的信息**——哪些事实是做判断前必须补上的。

允许出现第三条路（混合方案）：如果分析中真的浮现出主导性的融合路径，如实报告，但不得用它逃避表态——除非它能严格优于两者，否则最终判断仍要在原选项间做出或明确宣告改题。

### 第四步：只问一个问题

提出**唯一一个**最可能改变结论的问题，并说明为什么是它。一次只问一个：多个问题会稀释用户思考的聚焦度，而这个问题本身就是论证质量的试金石。

### 第五步：等待回答，然后明确判断

用户回答后，输出最终交付物，四项缺一不可：

1. **明确判断**——选 A 或选 B（或宣告改题），禁止"两者都可以"式的骑墙；
2. **理由**——结合用户回答给出的、可追溯到前面论证的依据链；
3. **适用条件**——这个判断在什么前提下成立；
4. **下一步行动**——拿到结论后应该立即做什么，以及什么信号出现时应当推翻本判断（给判断装上可逆开关）。

## 为什么这样设计

- **先重述再论证**：一半的决策错误源于解错了题。重述确认的成本极低，防呆收益极高。
- **对称是对 quality 的约束，不只是对公平的姿态**：强制等长等深的双边陈述，能有效对冲分析者自己的隐性偏好。
- **要求写下"最难回答的反对意见"**：这是钢铁人区别于稻草人的关键动作——每一方都必须直面自己最疼的一击，噪音理由自然被挤掉。
- **只问一个问题的收敛设计**：能够改变结论的信息通常只有一两条；把这个筛选过程显式化，用户的回答才能精准命中要害。
- **判断不许骑墙**：决策辅助的价值在于承担表态责任。"看你自己"等于零输出；但通过"适用条件 + 推翻信号"，表态又保持了诚实与可修正。

## 用户可复制的 Prompt 模板

```text
我需要做的决定是：【写清问题、两个选项、目标和现实约束】。

先别急着回答，也别默认我已经把问题想清楚。请先做一次双向钢人论证：

1. 用最完整、有力的方式，重述我真正需要做出的选择；
2. 分别给出支持两个方向的最强理由、适用条件、最大收益、最大风险，以及最难回答的反对意见；
3. 找出双方真正的分歧、最可能改变结论的关键变量，以及还需要补充的信息；
4. 只问我一个最可能改变结论的问题。

等我回答以后，再给出明确判断、理由、适用条件和下一步行动。
```

## 边界与注意

- 论证语言跟随用户语言。
- 用户的问题若是三个及以上的多选题，先让用户收敛到两个（淘汰明显劣势项）再启动；实在无法收敛时，可两两分组接力论证，但要说明这样做的局限。
- 时间紧的小事不值得全套流程： Dinner 吃什么这类低风险决策直接给建议即可，本技能是为"值得认真权衡的选择"设计的。
- 判断时要标注置信度：如果关键变量的答案仍高度不确定，明说"此判断的可信度取决于 X"，比假装确定更负责。
- 涉及重大不可逆决策（辞职、结婚、大额支出）时，在最终判断里主动建议用户补一步外部验证（咨询当事人/专业人士），而不是独自包办结论。
