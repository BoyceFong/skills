# 第一性原理（First Principles）

## 这个技能解决什么

很多问题的解法会陷入**路径依赖**：一开始选了一个方向，之后所有修正都是在这个方向上打补丁。补丁越打越多，系统越来越复杂，但问题根源从未被触碰。第一性原理的做法是：**把问题拆回不可再分的基本事实和真实目标，暂时放下行业惯例与现成方案，从本质重新推导一条可行路径**，并明确指出原方案只是在修补哪些表面、新路径成立的前提、以及验证它的第一步。

你的角色不是"在现有方案上做优化"，而是"回到起点重新设计"。

## 什么时候做

- 方案上各种打补丁，越改越复杂时。
- 改组织流程、做产品架构、修复杂系统时。
- 面对被行业惯例束缚、陷入路径依赖的老问题。
- 任何想回到问题本质重新思考的时候（这是它的万能适用场景）。

如果问题简单、方案清晰、没有路径依赖的迹象，不要使用本技能，直接回答。

## 工作流程

### 第一步：接收问题，暂缓方案

确认用户想解决的问题，明确本次不做"增量修补"，而是回到底层重新推导。先不要给出任何方案，也不要引用现成做法。

### 第二步：拆解为四个层面

把问题拆开，逐项区分并列出：

1. **已经确认、无法绕开的基本事实** —— 物理规律、系统边界、已被验证的数据、不可谈判的约束。这些是推导的起点，不能动摇。
2. **习惯性接受、却没有验证过的假设** —— "行业都是这么做的""客户肯定要这个""性能一定会成为瓶颈"。它们看起来像事实，实际上只是未经验证的惯例或猜测。
3. **真正想实现的目标** —— 不是中间手段，而是终点状态。不断追问"这个目标是为了什么"，直到得到不再需要理由的答案。
4. **现实中的资源与约束** —— 时间、人力、预算、技术栈、合规要求等。约束不是敌人，它们定义了可行解所在的空间。

拆解时，重点找出**被当作事实的假设**——这是路径依赖藏身的地方。

### 第三步：从底层重新推导

暂时放下行业惯例和现成方案，只基于"基本事实 + 真实目标 + 资源约束"推导可行路径：

- 从目标倒推：为了让目标成立，什么必须为真？
- 用基本事实过滤：哪些路径被事实排除，哪些其实从未被排除过（只是被惯例排除）？
- 用约束裁剪：在剩余空间里，哪条路径是最简单、最直接、改动最小的？

推导过程中如果发现某个"约束"其实是未验证的假设，把它移回第二类，不要让它参与裁剪。

### 第四步：输出四段式结论

按以下固定结构整理：

1. **原方案中只在修补表面的部分** —— 明确指出原方案用补丁掩盖了哪些根本问题。
2. **从基本事实重新推导出的新路径** —— 具体、可执行，而不是口号。
3. **这条路径成立的前提** —— 新路径依赖哪些条件，这些条件当前是否满足。
4. **验证它的第一步** —— 一个最小、低成本、能最快证伪或证实新路径的实验。

## 为什么这样设计

- **事实与假设分开**：路径依赖的根源是把"惯例"当成了"必然"。把假设单独列出来，才能看到哪些路其实一直没被堵死。
- **目标要追到终点**：大多数"目标"其实是手段（"我要重构系统"是为了"更快交付"，而后者是为了"活下去"）。目标层没挖到底，推导就会在错误的层次上发生。
- **约束是设计空间**：与其抱怨资源不足，不如把约束当作筛选条件——它让"可行路径"从无限变成有限，反而让推导更清晰。
- **惯例暂时放下，但不是永久丢弃**：重新推导出的路径如果和惯例一致，那是推导的结果，而不是因为"大家都这么做"。
- **先验证再相信**：新路径在验证之前只是假设。给出第一步实验，是把"听起来有道理"变成"可以检验"的关键一步。
- **指出原方案的表面修补**：这不是批评，而是让用户看见补丁的代价——复杂度在哪里累积、为什么根治不了。

## 用户可复制的 Prompt 模板

当用户想独立使用这套推导（不依赖本技能自动触发）时，可以给他们这份模板：

```text
我想解决的问题是：【填写你的问题】。

请用第一性原理把它拆回最底层，区分：
1. 已经确认、无法绕开的基本事实；
2. 习惯性接受、却没有验证过的假设；
3. 真正想实现的目标；
4. 现实中的资源与约束。

暂时放下行业惯例和现成方案，只从基本事实、目标和约束出发，重新推导可行路径。

最后请输出：
1. 原方案中只在修补表面的部分；
2. 从基本事实重新推导出的新路径；
3. 这条路径成立的前提；
4. 验证它的第一步。
```

## 边界与注意

- 语言跟随用户语言。
- 如果用户明确表示"只要打补丁，不要推倒重来"，尊重对方，不要强行使用本技能。
- 第一性原理推导出的新路径可能更简单，也可能更激进；在给出建议时，把新路径的前提和验证第一步写清楚，让用户自己判断风险。
- 如果拆解后发现基本事实不足（例如关键数据缺失），在四段式结论里明确指出"缺少哪块事实"比硬推一个结论更有价值。
