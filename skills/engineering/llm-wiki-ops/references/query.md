# 查询流程（Query）

## 步骤

1. **定位**：先读取「索引」文档，根据用户查询的关键词定位相关词条、资料卡和文章。
2. **深入阅读**：读取定位到的相关文档全文（不跳过）。
3. **综合**：基于文档内容综合出答案，每个关键论断标注来源文档。
4. **归档**（可选）：如果查询产生了有价值的新连接、比较或分析，将其归档回 wiki：
   - 创建新词条或更新已有词条
   - 更新索引
   - 在更新日志追加 `query` 条目

## 查询类型

### 事实查询
- 用户问“XX是什么”“XX有什么特点”
- 直接读取对应词条，给出定义和关键事实

### 比较查询
- 用户问“XX和YY有什么区别”“哪个更好”
- 读取两个词条，从资料中提取对比维度
- 如果资料中没有直接对比，基于各自的关键事实做客观对比，标注“基于资料综合”

### 关系查询
- 用户问“XX和YY有什么关系”
- 读取两个词条的「与其他词条的关系」部分
- 如果关系不完整，基于资料补充，并更新词条的双链

### 主题查询
- 用户问“最近有什么关于XX的动态”
- 先查索引中相关词条
- 如果绑定了 AIHOT 技能，可结合实时资讯查询
- 将有价值的新动态入库（走 ingest 流程）

## 输出规范

- 答案基于知识库内容，不凭记忆编造
- 关键事实标注来源（如“（来源：资料卡：AIHOT 日报 2026-08-30）”）
- 如果知识库中没有相关内容，明确告知“知识库中暂无相关资料”，并询问是否需要入库新资料
- 涉及数字、日期等精确信息时，回原文核对，不臆测

## 归档触发条件

以下情况应将查询结果归档回 wiki：
- 发现了两个词条之间的新关系
- 对多个词条做了有价值的比较分析
- 用户的问题揭示了知识库中的空白（缺页、矛盾、过期）
- 查询产生了可以沉淀为新概念的综合结论

归档后必须更新索引和日志。
