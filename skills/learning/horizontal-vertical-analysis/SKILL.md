# 横纵分析法（Horizontal-Vertical Analysis）

## 这个技能解决什么

浅层研究的通病是"只见当下"：要么只描述现状、不知道现状是怎么来的，要么只罗列历史、不知道它在同行中的相对位置。横纵分析法用两条轴解决这个问题：

- **纵轴**：看对象怎么走到今天（时间线 / 演化史）——它的诞生背景、关键转折、早期选择如何沉淀为今天的能力与包袱；
- **横轴**：看对象今天与竞品的差异——用统一维度比较强弱与独特性，理解用户为什么选它、又为什么离开它。

两条轴交叉起来，才能看到"历史选择如何塑造今天"，并进一步推演未来路径。最终产出一份 **10000～30000 字、带来源标注、可追溯**的深度报告。

你的角色是"研究者"，不是"评论员"：结论必须能追溯到证据。

## 什么时候做

- 想深度、系统研究某个产品、公司、人物、技术、行业或事件。
- 想在半小时内对一个陌生领域建立基本框架。
- 做市场 / 行业 / 公司研究、调研竞品格局。
- 需要带来源标注、可追溯的深度研究报告。
- 用户明确要求"横纵分析""深度研究""竞品分析"。

如果用户只需要一个简短的事实性答案，不要使用本技能，直接回答。

## 工作流程

### 第一步：确定研究对象与范围

接收研究对象（产品、公司、人物、技术、行业或事件）。如果对象有歧义（同名产品、不同市场、不同时期），先确认范围；不确定时选择最常见定义并说明。研究截止时间为执行当天。

### 第二步：纵向分析（时间线 / 演化史）

回答三个问题：

1. **诞生**：它在什么背景和需求下诞生，关键推动者是谁；
2. **演化**：它经历了哪些重要转折、成功和失败；
3. **沉淀**：哪些早期选择变成了今天的能力、路径依赖或包袱。

纵向分析的关键是把"当时的决策"和"今天的后果"连起来：每个今天看起来很自然的特点，几乎都能在历史上找到它被选择的那一刻。

### 第三步：横向分析（竞品对比）

回答三个问题：

1. **选谁比**：选择最值得比较的对象，并说明为什么选它们（可比性、市场份额、替代关系）；
2. **怎么比**：用统一维度比较各自的强项、短板和独特性（维度要一致，否则对比失真）；
3. **为什么赢/输**：解释用户、客户或市场为什么选择它，又为什么放弃它。

横向分析的目的不是排名，而是定位：它在竞争空间里到底站在哪里。

### 第四步：两条轴合起来，判断未来

1. **延续性**：过去形成的能力、路径依赖和约束会怎样影响未来；
2. **三条路径**：未来最可能出现哪 3 条路径；
3. **前提与信号**：每条路径出现的前提和预警信号是什么。

未来判断必须可证伪：没有前提和预警信号的"预测"只是猜测。

### 第五步：遵守证据规则

研究全程执行四条规则：

1. **优先一手来源**：官方资料、原始数据、论文、财报和访谈，优先于二手转述；
2. **就近标注**：重要结论旁边标注来源与日期；
3. **分层书写**：事实、推断和观点分开写，读者始终能区分"它确实如此"和"我认为它如此"；
4. **诚实面对空白**：遇到冲突信息时并列呈现；找不到证据时明确写"暂未核实"，不要用推测填补。

### 第六步：按固定顺序输出

报告按以下顺序组织，**语言尽量通俗，不要堆砌资料**：

1. **核心结论** —— 先给最要紧的判断，方便读者 30 秒抓住重点；
2. **关键时间线** —— 纵向分析的浓缩呈现；
3. **横向对比表** —— 统一维度下的竞品对比；
4. **详细分析** —— 纵轴与横轴的完整论证；
5. **未来判断** —— 3 条路径 + 前提 + 预警信号；
6. **仍待确认的问题** —— 证据不足、需要进一步核实的事项。

报告总长度控制在 **10000～30000 字**：低于下限说明研究不够深，高于上限说明在堆砌资料。

## 为什么这样设计

- **纵轴回答"为什么是现在这样"**：现状不是凭空出现的，而是历史选择的累积结果。只讲现状的研究无法解释"为什么"，也就无法判断"会怎样"。
- **横轴回答"它相对谁怎样"**：能力与短板只有放在竞争参照系里才有意义。没有参照的"很强"是空洞的。
- **两轴交叉才产生判断力**：历史解释了能力从哪来，对比解释了能力值多少；只有两者交汇，才能推导未来路径，而不是从单轴外推。
- **可追溯是研究报告的底线**：结论没有来源就等于没有结论。就近标注让读者可以逐条核验，也让作者不敢信口开河。
- **事实/推断/观点分层**：三者混写是研究报告最常见的污染源。分开写之后，读者的信任才有落脚点。
- **3 条路径 + 前提 + 信号**：未来不可预测，但可以准备。给出前提和预警信号，等于把判断变成了可以持续验证的假设。
- **长度与通俗度**：10000 字是为了保证深度，通俗是为了保证可读。堆砌资料是研究不足的伪装，不是深度。

## 执行提示

- 本技能擅长设计研究框架和结构；实际收集证据时，主动使用可用的检索与联网工具（网页搜索、打开来源页面、官方文档、财报等），不要凭记忆编造事实。
- 作者建议：配合各 AI 产品的「深度研究」功能一起使用，效果才是满血版——本技能负责框架与判断，深度研究工具负责大规模搜集与交叉验证。
- 若检索能力受限导致证据不足，优先保证报告诚实（标注"暂未核实"），而不是编造来源。

## 用户可复制的 Prompt 模板

当用户想独立使用这套分析法（不依赖本技能自动触发）时，可以给他们这份模板：

```text
研究对象是：【填写产品、公司、人物、技术、行业或事件】。

请使用横纵分析法，对它完成一份可追溯的深度研究。研究截止时间为执行当天。

纵向分析：
1. 它在什么背景和需求下诞生，关键推动者是谁；
2. 它经历了哪些重要转折、成功和失败；
3. 哪些早期选择变成了今天的能力、路径依赖或包袱。

横向分析：
1. 选择最值得比较的对象，并说明为什么选它们；
2. 用统一维度比较各自的强项、短板和独特性；
3. 解释用户、客户或市场为什么选择它，又为什么放弃它。

把两条轴合起来，继续判断：
1. 过去形成的能力、路径依赖和约束会怎样影响未来；
2. 未来最可能出现哪 3 条路径；
3. 每条路径出现的前提和预警信号是什么。

请遵守这些证据规则：
1. 优先使用官方资料、原始数据、论文、财报和访谈等一手来源；
2. 重要结论就近标注来源与日期；
3. 事实、推断和观点分开写；
4. 遇到冲突信息时并列呈现，找不到证据时明确写"暂未核实"。

最后按以下顺序输出：核心结论、关键时间线、横向对比表、详细分析、未来判断、仍待确认的问题。报告需要在 10000～30000 字之间，语言尽量通俗，不要堆砌资料。
```

## 边界与注意

- 语言跟随用户语言。
- 如果用户只想要简短回答或单点事实，不要启动完整流程。
- 研究对象信息量小时（例如小众项目公开资料极少），报告长度允许靠近下限，并把"资料有限"作为第一条仍待确认的问题写清楚。
- 报告里的"未来判断"是对当前证据的推断，不是承诺；结尾应提醒读者信号比预测更重要。
